4.1 GET /r/:projectKey

クエリはすべて文字列で meta に入る（例：?app_version=1.2.0&os=ios）。ただし kinds（カンマ区切り）は表示する種別の指定に、lang（ja / en）は最初に表示する言語の指定に使う。meta のキーは英数字・_・- のみ受け付ける。存在しないキーは 404。

4.3 GET /setup

GitHub App は「インストール時にユーザー認証（OAuth）を求める」を有効にし、コールバック先をこの URL にする。GitHub から installation_id と code を受け取る。code をユーザートークンに換え、GET /user/installations/{installation_id}/repositories でそのユーザー自身がアクセスできるリポジトリだけを取り（MUST。Organization のメンバーに権限外のリポジトリを見せないため）、それらのプロジェクトを作りキーを一覧表示する。code がなければ GitHub の認可画面へリダイレクトする。state は「ランダム値.対象（installation_id か keys）」とし、同じ値を短命の HttpOnly・SameSite=Lax クッキー（pi_state、Path=/setup、10 分）にも入れる。戻ってきた state がクッキーと一致しない code は使わず、認可からやり直す（MUST。他人の code を踏ませて他人のキーを見せる「ログイン CSRF」を防ぐ）。GitHub から戻ってきたのにクッキーが無い場合は、やり直すと行き来が止まらないので、Cookie を許可するよう案内して止める。確認できなければ 403 で、リポジトリ名もキーも出さない（非公開リポジトリの名前が漏れるのを防ぐ）。IP ごとに回数を制限する。

4.5 GET /api/keys と CLI

CLI やスクリプト・AI エージェントが作者のキーを取得するための API。Authorization: Bearer <GitHub ユーザートークン> を受け取る。

  • トークンは GitHub App のデバイスフローで作者自身がブラウザでログインして得る（App 設定で Device Flow を有効にする）。CLI・AI はログインや許可の操作をしない（MUST）。
  • サーバーは POST /applications/{client_id}/token で、そのトークンがこの App 用に発行されたものかを確かめる（MUST。他の App のトークンや PAT を拒否する）。
  • 返すのは、そのユーザーがアクセスできるリポジトリだけ（4.3 と同じ規則）。トークンは保存しない。IP ごとに回数を制限する。
  • 応答：{ ok: true, endpoint, keys: [{ repo, key, stopped }] }。失敗：401 unauthorized / 429 rate_limited / 502 upstream_error。

CLI：npx github:ninjin0802/posissue keys [--json] [--endpoint URL]（リポジトリの cli/posissue.mjs、依存なし、Node 18+）。案内は標準エラー、結果は標準出力に出す。

4.4 POST /webhook

X-Hub-Signature-256 を HMAC-SHA256 で検証する（MUST）。扱うイベント：installation.deleted → 該当プロジェクトを全停止、installation_repositories.removed → 該当リポジトリのプロジェクトを停止。
