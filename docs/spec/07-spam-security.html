7. スパム対策とセキュリティ

安い検査から順に行い、最初に失敗したところで止める。順番は MUST。

7.1 検査の順序

#検査失敗時
0本文が 20KB を超える（読む前に Content-Length で判定）400 invalid_input
1JSON 形式・型・文字数（3.1 の制約）400 invalid_input
2ハニーポット hp が空でない422 spam
3elapsedMs < 3000422 spam
4タイトルと全項目の URL 数 > 2（http(s)://、www.、Markdown のリンク・画像 ](、プロトコル相対 //host を数える）422 spam
5プロジェクトが存在し有効404 unknown_project
6Origin が自ドメインか許可リストに含まれる（リストが空でなければ）。フォームページは iframe 内から自ドメインとして送るので、埋め込み元の制限は 7.3 の frame-ancestors で行う403 forbidden_origin
7IP ごとの投稿数（1 分に 2 件。Rate Limiting バインディングの期間は 10 秒か 60 秒のみ）429 rate_limited
8Turnstile トークンを siteverify で検証し、結果の hostname が自ドメインであることも確かめる403 captcha_failed
9プロジェクトの日次件数（既定 50）429 rate_limited
10同一内容（キー・種別・タイトル・全項目）のハッシュが 24 時間以内にある。Issue 作成に失敗したらハッシュを消して再送できるようにする409 duplicate

Turnstile は外部呼び出しのため、無料の検査（1〜7）の後に置く。

7.2 本文の無害化（MUST）

  • @ の直後にゼロ幅スペースを入れ、メンション通知を無効にする。
  • #数字 の # の直後にゼロ幅スペースを入れ、Issue 参照による通知を防ぐ。
  • 環境情報の表の値は
  • 環境情報の表では | とバッククォート、改行をエスケープする。
    • lt;code
  • 環境情報の表では | とバッククォート、改行をエスケープする。
    • gt;     に入れ、Markdown/HTML で意味を持つ記号（. : [ ] ( ) など）をすべて文字参照にして、リンクにならないようにする。
  • HTML タグはそのまま文字として残してよい（GitHub 側で無害化される）。

7.3 その他のセキュリティ

  • フォームページの CSP frame-ancestors に許可リストを入れ、許可していないサイトには埋め込めないようにする（空なら *）。
  • フォームページは Content-Security-Policy を付け、スクリプトは自身と Turnstile のみ許可。
  • Webhook は署名を検証し、比較は時間一定の比較を行う。
  • 秘密情報（App 鍵・OAuth の client secret・Turnstile secret）は Workers Secrets のみに置く。
  • スクリプトのない案内ページ（/setup など）にも CSP（default-src 'none'、frame-ancestors 'none'）を付ける。
  • フォームには「送信内容とページの URL・ブラウザの情報が Issue に掲載される」ことを明記する。
  • 報告者の個人情報は保存しない（5章）。

7.4 悪用時の対応

運営は UPDATE projects SET banned = 1 WHERE repo = ? で止める。/setup は認証なしで呼べるため、banned は /setup では解除しない（MUST）。アンインストール等で active = 0 になったものは、再インストール時に新しいキーで復活する。
